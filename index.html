How this works

Register beneficiaries one by one or import your existing CSV files (any column layout — you map the columns). Everything is stored in this browser's local database on this computer; nothing is sent anywhere. The Duplicates tab cross-references the whole dataset: exact matches on National ID and phone, plus fuzzy matching on names (typos, swapped name order, different spellings) corroborated by date of birth, sex and location. New registrations are also checked live against the existing records before saving.

Duplicate detection — full dataset scan

Cross-references every record against the rest of the dataset. Sure matches: identical National ID. Probable/possible matches: similar names (phonetic + edit-distance, handles swapped name order and typos) weighted together with date of birth, phone, sex and location. Runs in the background — you can keep using other tabs.

Matching sensitivity

Lower thresholds find more candidates but more false positives. Pairs scoring above the "possible" threshold are grouped; above "probable" they are flagged red. Very common name blocks larger than the block cap are skipped for speed (exact ID/phone matches are never skipped).

Data tools

Demo data creates realistic sample records including ~3% planted duplicates (typos, swapped names, shared IDs) so you can try the scan.

About storage & capacity

Data lives in this browser's IndexedDB for this page — it persists across restarts and works fully offline, and browsers allow it to grow to many gigabytes (enough for millions of records). It is per-browser and per-computer: to move data, use Export CSV here and Import CSV on the other machine. Regular exports are your backup — clearing the browser's site data would erase the registry.
